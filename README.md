# 就活データ横比較

有価証券報告書だけを出典に、同業他社を1つの表に並べる静的サイト。

平均年収も男女の賃金の差異も、1社ずつなら調べれば出てくる。しかし**同業7社を1つの表に並べたもの**は
どこにもない。就活情報サイトは企業から広告費を受け取る側なので、企業を不利に並べられないからである。
このサイトは掲載企業から1円も受け取らない。

対象：35業界1,549社・計7,663件の有価証券報告書（直近5期）。決算期は3月・12月・2月・8月が混在する。
対象は東証プライム上場企業全銘柄＋その他主要企業。業種・EDINETコードの突合には
JPX「[東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/tvdivq0000001vg2-att/data_j.xls)」
（33業種区分・証券コード）を使用（アクセス日 2026-07-11、robots.txt確認済み）。
サイトに表示する数値そのものはEDINETの有価証券報告書のみを出典とする。

## 設計上の鉄則

1. **数値をClaudeに読ませない。** XBRL/CSVから機械的に抽出する。Claudeは文章化しか担当しない。
2. **有報PDFが正本、XBRLは照合相手。** XBRLの標準タグ `NumberOfEmployees@NonConsolidatedMember` は
   有報の表に載る従業員数とは限らず（三菱商事・双日・三菱地所・SOMPO HDなどで不一致）、
   **平均年間給与の分母はその表の値**である。`verify_employees.py` が全件をPDFと突き合わせる。
   PDFの読み方は2通り用意し、テキスト順の読み取りがXBRLのどちらのタグとも一致しないときだけ
   セル座標方式で読み直す（多行表の商船三井・スカイマーク、転置表の本田技研で必要）。
   どちらの読み方でもXBRLと一致しなければ、その数字は**公開しない**。
3. **データが無い項目は「非公表」と書く。** 0や平均値で埋めない。埋めた瞬間に唯一の資産（信頼）を失う。
4. **DBを作らない。** 数MBのJSONをGitに直接コミットする。Git履歴がそのまま数値の監査証跡になる。

## 誠実に見せるための規則（`generate.py` が守る）

- **持株会社の平均年収は本体の数字**であって事業会社（三菱UFJ銀行など）の水準ではない → 警告を出す
- **「男女の賃金の差異」は男性を100としたときの女性の賃金の割合**であって「差」ではない
- **男性育休取得率には2方式ある**（71条の6第2号方式は育児目的休暇を含み高く出る）→ 方式を併記し順位を付けない
- **従業員数は連結と提出会社を分ける**。平均年間給与の分母は提出会社
- **算定基準が変わった年度をまたぐ増減率は出さない**（三井不動産・三菱地所）。有報の注記をそのまま掲示する
- **3年以内離職率は載せない。** 大手企業は公的に開示しておらず、しょくばらぼにも掲載がない（全掲載148,228社のうち埋めているのは1.8%＝中小企業層のみ）
- **最新の有報が他社より一世代古い会社は「古い期」と明示する**（アサヒGHDは2025年12月期を未提出）

## 使い方

```bash
python fetch_edinet.py find --from 2026-06-01 --to 2026-06-30 --append  # 書類一覧 → data/doc_index.csv
python fetch_edinet.py get --types 5,2                          # XBRL(CSV) と PDF を取得（1req/秒。カンマ区切り）
python verify_employees.py                                      # 有報PDFと突き合わせ → data/employees_verified.csv
python extract.py                                               # 機械抽出 → data/companies/*.json
python extract_financials.py                                    # 任意。財務（連結）→ data/financials/*.json
python verify_financials.py                                     # 任意。財務の検算 → data/financials_review.csv
python extract_overseas.py                                      # 任意。海外売上高比率 → data/overseas/*.json
python generate.py                                              # 静的サイト → site/
python write_prose.py --submit / --collect                      # 任意。Claudeが解説文だけ書く（数値は渡すだけ）
python tools/select_saiyo_pilot.py                               # 任意。新卒採用枠の対象企業（主要12業界の全社）を選ぶ → data/saiyo_pilot.json
python fetch_saiyo.py                                            # 任意。採用サイトを深追いして生テキストを集める → data/saiyo_raw/
python tools/clean_saiyo_raw.py                                  # 任意。複数ページ間の共通ナビ文言を間引く → data/saiyo_clean/
python tools/dump_saiyo_batch.py --start 0 --count 20 --out x.txt # 任意。生テキストをN社ずつ1ファイルにまとめる（Claudeが読んで構造化する下ごしらえ）
```

`write_prose.py` を実行しなくてもサイトは完全に成立する。文章は装飾であり、商品は数字の並びである。
`extract_financials.py` / `extract_overseas.py` も同様に任意で、`data/financials` `data/overseas` が
空でも `generate.py` は通る（財務の節とランキングの一部が出なくなるだけ）。留学中に壊れる部品を増やさないため、
これらは既存の抽出とは別ファイルに分けてある。

## 出せるもの・出せないもの（実測にもとづく）

最新の有報1,549件を機械的に走査して、載せられるかどうかを確かめた結果:

| 項目 | 歩留まり | 判断 |
|---|---|---|
| 売上高／経常収益・純利益・総資産・自己資本比率・ROE | 99〜100% | 掲載する |
| 営業利益 | 93% | 掲載する（IFRS・米国基準は表示しない会社がある） |
| 経常利益 | 85% | 掲載する（IFRSに経常利益の概念は無い） |
| 海外売上高比率 | 全体7.7%／地域情報のある大手の67% | **取れた会社だけ**掲載する |
| 離職率 | 言及34%・数値まで取れるのは13% | **掲載しない**（下記） |
| 有給取得率・平均残業時間 | 21%・18% | 掲載しない |
| エンゲージメントスコア | 言及76% | 掲載しない（5点満点・100点・肯定回答率が混在し比較できない） |

**離職率を載せない理由**は歩留まりだけではない。実際に拾えた記述を見ると、
「正社員離職率4.5%以下（2031年3月期）」は中期経営計画の**目標値**、
「育児休業からの定着率100%」は**別の指標**、「主要4社依願離職率11.0%」は**対象範囲が限定**されている。
実績・目標・対象範囲を機械的に判別できない。この品質のものを載せれば、
このサイトの唯一の資産である信頼を削ることになる。

## 新卒の採用枠（2026-08-17、主要12業界の全609社が対象）

有報には「採用枠」（総合職/エリア職、事務系/技術系など）のような情報は無い。ここだけは
**採用ページ自身**を出典にする。`fetch_saiyo.py` が公式採用ページを2〜3階層だけ深追いして
プレーンテキストを集め（robots.txt厳守・1ホスト1.2秒間隔はfetch_links.pyと同じ）、
このセッションが直接読んで `data/saiyo/{code}.json` に構造化した（write_prose.pyが事業内容の
要約をAPI無しで直接書いたのと同じ立て付け）。書かれていないことは書かない。1トラックごとに
**条件・概要・時期**の3項目に分けて書き、原文に明記されていない項目は null のままにする。

対象は総合商社・銀行業・保険業・証券・電気機器・情報通信・食料品・医薬品・化学・輸送用機器・
小売・建設業の12業界**全社**（当初はパイロット100社だったが、業界を絞ってでも網羅する方が
一部だけ拾うより誠実だと判断し全社に拡大）。609社のうち220社で構造化できた。残りは採用サイトが
JSで動的描画されている、採用トップが薄いランディングページで実際のコース説明に辿り着けない、
条件・給与など具体的な記述が無く社風の紹介にとどまる、などの理由で対象外とし、その場合は今まで
通りリンクだけを表示する（推測のURLは辿らない）。

企業ページ1,500枚超をこのデータのためだけに再生成しないよう、`generate.py` はHTMLに焼き込まず
`data/saiyo/*.json` を1本の `data/saiyo.json`（スラッグ→データ）にまとめて出力するだけにとどめる。
実際にDOMへ差し込むのは各企業ページのJS（`initSaiyoInject`、`app.js` 内）で、自分のページの
スラッグをそのJSONで引いて実行時に「新卒の採用枠」セクションを追加する。対象社が増えても
`data/saiyo.json` を更新して差し替えるだけでよく、UIを触る作業と競合しない。

## 学部・興味から絞る診断（`tekisei.py`）

`shindan.py`（就活の軸診断）は有報の数値で会社を並べ替えるが、学部や興味は有報に出てこない。
この診断は逆に、**業界レベルの一般的な傾向**（`GROUP_TAGS`。技術系採用の有無など業種の実態に
もとづく機械的な対応づけで、個々の企業の採用方針を示すものではない）で全1,549社を対象に
業界・企業を絞り込む。会社ごとに `data/saiyo/{code}.json` の対象学部の記載があれば、
一般的な傾向より優先してその原文を出典付きで表示する。一般論より一次情報を信じる、
という設計はこのサイト全体の原則と同じ。

## 出典とライセンス

- データ：EDINET閲覧（提出）サイト（金融庁）
- ライセンス：[公共データ利用規約（PDL1.0）](https://www.digital.go.jp/resources/open_data/public_data_license_v1.0)
- 本リポジトリの数値は、上記の有価証券報告書を当プロジェクトが機械的に抽出・整形したものです

EDINET利用規約は「短時間における大量のアクセス」を禁じている。`fetch_edinet.py` は全リクエストを
**1件/秒**に強制し、取得済みの書類は再取得しない。アクセスログは `logs/edinet_access.log` に残る。

数値は公的な一次情報から機械的に抽出したものだが、正確性を保証するものではない。
最終的な判断は必ず原典（有価証券報告書）を確認すること。
